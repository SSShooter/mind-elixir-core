# 2026-09-29

## 调研：mind-elixir-core 的 RTL（阿拉伯语）文本支持

**问题**：现在能支持 RTL 语言吗（例如阿拉伯语）？

**结论：不能。** 库里没有任何文本方向机制，阿拉伯语按 LTR 段落方向渲染。

**静态证据**（全仓 `rtl|arabic|bidi|dir=` 扫描，除 node_modules/dist）：
- `src/index.css:55` 的 `.lhs { direction: rtl }` 是**布局技巧**（让 LHS 分支的子节点/展开按钮落位），
  不是文本方向：同一条规则里 `:62 .me-tpc { direction: ltr }` 把主题文本**显式重置回 LTR**。
- `src/index.css:303 #input-box { direction: ltr }` —— 编辑框硬编码 LTR。
- 没有任何地方设 `dir` 属性 / `unicode-bidi`；`Options` 里的 `direction` 是**布局方向 0/1/2/3**，
  与文本 bidi 无关，宿主无法通过配置开启 RTL。
- 物理属性残留（改 RTL 后会跑到错误一侧）：`.hyper-link { margin-left }`、`.icons { margin-left }`、
  `.tags span { margin: 4px 4px 0 0 }`、outliner `.outline-item-topic ul/ol { padding-left: 1.25rem }`、
  outliner `.katex-display { text-align: left }`。

**探针实测**（Playwright，临时 spec 跑完已移出仓库到 /tmp/rtl-probe.spec.ts）：
- 判别式：`مرحبا!` 的**尾部中立字符**——RTL 段落里 `!` 必须落在词**左**侧，LTR 段落里落在**右**侧。
- 基线：RHS 节点 `first="م"@822.0 last="!"@830.1` → `!` 在右侧，`RTL_OK=false`；LHS 节点同样 false
  （证实 `.lhs` 的 rtl 没传到文本）。两处 `direction=ltr`、`text-align=start`（=left）。
- **阳性对照**：内联 `style.direction='rtl'` → `RTL_OK` 翻转为 true，证明判别式有判别力。
- 多行 `مرحبا\nبالعالم`：两行**左边缘相同**（795.4）→ 左对齐，RTL 应为右边缘对齐。
- outliner 行：`direction=ltr`、`text-align=start`。
- 编辑框 `#input-box`：`direction=ltr`、`text-align=start`。

**宿主今天能自救的粒度**（已实测有效）：注入 `#map .me-tpc { direction: rtl }` 后，
RHS/LHS 两个节点 `RTL_OK=true`，多行变成**右边缘对齐**（`equalRightEdges=true`）。
但**编辑框收不到**：`input-box` 由 `dom.ts:202` append 到 `this.nodes`，**不是 `.me-tpc` 的后代**，
且 CSS 那条是 id 选择器优先级更高，必须单独再写一条 `#input-box { direction: rtl }`。
另外 `dom.ts` 搬家到 input-box 的 style 里只抄了 color/font-size/padding/margin/border，
**没抄 direction / text-align**。

**若要做成正式支持**，最小侵入的两个候选：节点 tpc + input-box 上加 `dir="auto"`
（按首个强字符定方向，天然适配"每个节点可能不同语言"）或 `unicode-bidi: plaintext`
（多行混合段落逐段定方向），再配合物理 → 逻辑属性（`margin-inline-start` 等）替换。
未做任何改动，仅调研。

## 实施：`rtl` 布尔选项 + `rtl` class 覆盖层

**用户拍板的方案**（否掉了我提的 `dir="auto"` / `unicode-bidi: plaintext` 两条）：
`Options.rtl?: boolean` → 为 true 时往容器加 `rtl` class → 一套 `rtl` class 下的覆盖 CSS。

**改动**：
- `src/types/index.ts`：`Options.rtl?: boolean`（放在 `direction` 之后，带 JSDoc 说明
  「仅文本方向，不镜像布局」，避免和 `direction` 混淆）。
- `src/index.ts`：构造器解构 `rtl` + `this.rtl = rtl ?? false`；
  `this.container.className = this.rtl ? 'map-container rtl' : 'map-container'`
  （全库仅此一处写 `container.className`，`space-pressed` 走 classList，不冲突）。
  `declare rtl: boolean` 由 `node gen-members.js` 生成，再 `biome format --write src/index.ts src/types/index.ts`。
- `src/index.css`：`.map-container` 块末尾新增 `&.rtl { ... }` 一段，即**全部**覆盖。
- `tests/generic-instance.type-test.ts`：+2 行（`mind.rtl` 是 `boolean`，`options.rtl` 是 `boolean | undefined`）。

**覆盖内容**：`.me-tpc` / `#input-box` / `.svg-label` / `.mind-elixir-ghost` /
`.context-menu .menu-list li` / `.tips` → `direction: rtl`；菜单快捷键 `span:last-child { float: left }`、
`.key { direction: ltr }`；`.hyper-link` / `.icons` 的 `margin-left` 翻到 `margin-right`。

**三个坑（想清楚才没写错）**：
1. `#input-box` 那条**必须单列**：它不是 `.me-tpc` 的后代（`dom.ts:202` append 到 `this.nodes`），
   且 `#input-box` 是 id 优先级；`&.rtl` 让它变 `.map-container.rtl #input-box` 才压得住。
2. `.lhs .me-tpc { direction: ltr }` 是 (0,2,0)，`.map-container.rtl .me-tpc` 是 (0,3,0) 才赢 ——
   否则左分支节点仍是 LTR（已断言）。
3. **`.tags span` 的 `margin: 4px 4px 0 0` 不能翻**：`.tags` 自身保持 `direction: ltr`（标签顺序
   不是文本），内部流仍是 LTR，翻边会把间隔挪到错的一侧。`.icons` 同理保留内部 `ltr`，只翻它的**外距**。
   菜单的 `float: left` 要打在 `span:last-child` 上，不能打 `.key` —— 无快捷键时第二个 span
   没有 class 但仍是 last-child。

**验证**：`playwright test` 204 绿（原 198 + 新增 `tests/rtl.spec.ts` 6 条）、
`tsc --noEmit -p tsconfig.json`、`tsc -p tsconfig.type-test.json`、`pnpm build`（先 `mv dist` 绕开
安全删除阈值）全部通过。`dist/MindElixir.css` 里编译出的选择器确认为 `.map-container.rtl ...`；
**`dist/Outliner.css` 仍是 map-container=0 / me-tpc=0 / rtl=0**（不变式未破）。

**两条「去掉修复就失败」对照**：① 去掉 `rtl` class 赋值 → rtl.spec 6 条全红；
② 保留 class、只删 `#input-box` 那条规则 → **只有**编辑框那条红（1 failed / 5 passed），
证明每条规则各自被守住、不是一条大选择器蒙过去。

**outliner 未覆盖**（独立样式表 + 独立入口，是否跟随后续再定）。

- `arabic-demo.html` —— 左右并排对照 + 页脚「看这几处」「没变的地方也是结论」两段。

**实测**（`/tmp/shot-arabic.mjs`：Node + Playwright 起真浏览器打真页面，非 spec）：

| 用例 | `rtl: false` | `rtl: true` |
|---|---|---|
| 根节点 `خريطة الذهن بالعربية!` | `!` 在右（first 233.9 < last 246.6） | `!` 在左（first 1040 > last 888.2） |
| `مرحبا بالعالم!` | `!` 在右 | `!` 在左 |
| 多行节点 | 两行左边缘对齐 | 两行右边缘对齐 |
| `#input-box`（真双击进编辑） | `ltr` | `rtl` |
| 右键菜单 `li` / `.key` | `ltr` | `rtl` / `ltr`（快捷键保持 LTR） |

页面无 console error / pageerror。

**踩到的坑**：
1. **`؟` 不是中立字符**：最初把根节点写成 `هل … ؟`，实测两种模式下 `؟` 落位**完全相同** ——
   U+061F 是强 RTL 字符，在 LTR 段落里也随阿拉伯语 run 走。换成 `!` 才有可见差异。
   推论已写进 `topics/rtl.md`：纯阿拉伯语句子两端无中立字符时，两种模式**看不出差别**
   （节点框收缩到文字宽度 + bidi 本来就把 RTL run 排成右起）。
2. **模块里的 `interface Window` 不与全局合并**：`dev.ts` 那套 `interface Window {...}` +
   `declare let window: Window` 在模块作用域是**本地**类型，于是 `window.addEventListener`
   报 TS2339。改用 `declare const window: Window & { ltr?: MindElixir; rtl?: MindElixir }`。
3. 自动化两点：Playwright 直接 `dblclick` 节点**不进编辑**，要先 `click` 选中再 `dblclick`；
   右键菜单是覆盖全屏的 `.context-menu`，关闭得 `mouse.click(5,5)`（Escape 无效）。

**验收**：`playwright test` 204 绿、`tsc --noEmit`、`tsc -p tsconfig.type-test.json`、
`biome check` 全过。`pnpm build` 未重跑 —— 只新增 demo 文件，不在 6 个构建入口里，`dist` 不受影响。

## 补记二：标签行（`.tags`）也跟随 rtl —— 推翻了上文的「`.tags span` 不要翻」

**用户**：「阿拉伯语使用者的习惯上来看 tag 是不是也 rtl？」→ **是，两处都要**，而且这是上文的
判断错了，不是新需求。

**根因**：`.tags { direction: ltr }` 是**基础表**里就有的（blame 到开源首个 commit）——我上轮只
「没动它」，还把它解释成「顺序不算文本」。实测站不住：

| 现象 | `rtl: true` 旧状态 | 翻 `.tags` 后 |
|---|---|---|
| 标签行从哪一侧起排 | **内容盒左缘**（`rowFromContentStart`≈0） | 右缘 |
| 同节点里文字 vs 标签行 | 文字在右、标签贴左，**差 110px**（`wide-tags` 节点） | 同侧贴边 |
| 屏幕上的 chip 顺序（3 个） | الأول → الثالث（与数据同序） | 反序，DOM 首 chip 在最右 |
| chip 内 `مرحبا!` 的 `!` | 词**右**侧（`relX last=22.2 > first=17.7`） | 词**左**侧（`first=20.5 > last=3`） |

**判据**（写进代码注释与 `topics/rtl.md`）：**这块东西是不是文字** —— 标签的内容与顺序都被读，
所以要翻；**图标不是文字**，一组符号没有阅读顺序，`.icons` 保留基础表 `ltr`，只翻外距。

**改动**：`src/index.css` 的 `&.rtl` 块里加两条（并重写了那段注释）：
```css
.tags { direction: rtl; span { margin: 4px 0 0 4px } }   /* 镜像基础表 margin: 4px 4px 0 0 */
```
**必须成对**：只翻 direction 不镜像 margin，那 4px 会留在行首一侧、行就不贴边了。
编译产物已确认 `.map-container.rtl .tags{direction:rtl}` / `… .tags span{margin:4px 0 0 4px}`；
`dist/Outliner.css` 仍是 `map-container=0 me-tpc=0 tags=0`（不变式未破）。

**新增测试**（`tests/rtl.spec.ts`，8 条 = 原 6 + 新 2）：数据里加了 `tags` 节点（长主题 + 3 个
阿拉伯语 chip，第一个是 `مرحبا!`），新增 `probeTags`：
- 「标签行按从右到左读、并贴在起始边」：`byX === dom.reverse()`、`|maxRight-contentRight| < 2.5`。
- 「chip 自己也是文本」：chip 内 `!` 与词首的左右关系，两图各自断言（同 `probeTopic` 的判别式）。
- **两个细节**：①「贴边」断言用 `Math.abs` —— 否则镜像 margin 少了 4px（`-4`）也满足 `< 2.5`，
  那条规则等于没测；②配一个反侧守卫（`另一侧 gap > 12`），否则行和文字一样宽时两侧都贴边、断言恒真。

**两条对照**：① 只删 `direction: rtl` → 新增那 2 条全红 / 其余 6 条绿；
② 只删 `span { margin }` → **只有**「贴边」那条红（1 failed / 7 passed）。

**验收**：`playwright test` **206 绿**、`tsc --noEmit`、`tsc -p tsconfig.type-test.json`、`pnpm build`
全过。`biome check src/index.css` 报的那条是**既有**问题（文件顶部 `font-family` 换行，HEAD 上一样报），
按仓库惯例不去 reformat。真浏览器复验：`/tmp/tags-shot.mjs` 按真实代码出图，RTL 侧标签行贴右、
拉丁 chip 行也按 RTL 顺序（`beta | alpha`）——这是**有意**的：行方向属于 UI，不属于 chip 的语言。

**顺带**：`src/exampleData/arabic.ts` 新增 `الوسوم` 组（3 chip 行 + `مرحبا!` 行）让 demo 能显形，
`arabic-demo.html` 页脚加两条看点。
