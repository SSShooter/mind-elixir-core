## 方向键巡航逻辑审计（keypress.ts）
用户问方向键巡航还有没有优化空间。通读 `src/plugin/keypress.ts` + 布局/选区相关代码，并用无头 Chromium 对着
现成 vite(23333) 的 test.html 跑了 8 项探针（脚本已删）。

**已验证为正确的（不要误报 bug）**：
- `selectParent` 的 DOM 链 `parentElement³.previousSibling.firstChild` 实际落在**父级 tpc**（不是 me-parent）——
  chldr.previousSibling = 父 p，p.firstChild = tpc（expander 是后 append 的，在 tpc 之后）。Enter 后续操作不炸。
- DOM 顺序 = 视觉顺序（lhs 的 `direction: rtl` 只翻水平，不影响纵向堆叠），Up/Down 与视觉一致。
- 根节点 Left/Right 选中对应侧中间节点、折叠节点 ArrowRight 静默无操作、末尾 sibling Down 自重选。

**找到的优化点（按价值排序）**：
1. 折叠分支死路：selectFirstChild 依赖子节点在 DOM（折叠即离开 DOM），ArrowRight/Down 对折叠节点是无操作。
   XMind 式做法：导航时 `expandNode(el, true, {silent:true})` 再选第一个孩子。
2. 边界死路：末尾 sibling + Down 自重选（探针实测），无 cousin 穿越到「父的下一个兄弟的第一个孩子」。
3. 多选锚点不一致：handleLeftRight 用 `currentNodes[0]`，handlePrevNext 用 `currentNode`（最后一个），
   selectDownParent/Child 用 `currentNode || currentNodes[0]` —— 三种锚点约定并存。
4. 大改动项：几何式（spatial）导航——目前纯逻辑遍历，跨子树的「视觉上移/下移」做不到。
5. 小项：handleLeftRight 的 `offsetParent.offsetParent.parentElement` 可换成现成的 `directionOf` +
   closest('.me-main')；边界自重选会白跑一次 clearSelection+scrollIntoView。
探针陷阱：page.keyboard.press 打到 body，container.onkeydown 收不到——必须对 container 派发
KeyboardEvent 或先点节点（点节点会让 container 获得焦点）。另：折叠节点子元素离开 DOM，
探针里先折叠再按 id 找子节点会 null。

## 修复 3：多选锚点统一（已落地）
`keypress.ts` 新增 `currentAnchor(mei)`（读 currentNodes 末位，空/undefined 安全），四处导航函数
（handleLeftRight / handlePrevNext / direction-3 的 Up、Down）全部改用它，不再出现
`currentNodes?.[0]` 与 `currentNode` 并存。回归测试加在 `tests/topic-select.spec.ts`
（Multi-select navigation anchors on the last-selected node），已做负对照：旧锚点下必挂。
关键实测事实：**selectNodes 的入参顺序不决定 currentNodes 顺序**——viselect 走 DOM 遍历序 +
「已选中保留位置、新增追加」；先 click(child3) 再 selectNodes([child1, child3]) 得
`[child3, child1]`，锚点是 child1。写这类测试别假设数组入参序。
四项绿：207 playwright + 双 tsc + pnpm build（dist 先 mv 走，Outliner.js 洁净度 grep=0 通过）。

## 修复 2：边界 cousin 穿越（已落地）
`keypress.ts` 新增 `boundaryBranch(wrapper, direction)`：末尾 sibling 按 Down / 开头 sibling 按 Up
时向上找最近有分支的祖先，进入该分支**第一层**孩子（Down 取 firstElementChild、Up 取 lastElementChild；
分支无孩子或折叠则取分支 tpc 本身）。一层而非叶子深度——保持「Up/Down 不下钻层级」语义。
无分支可走时保留原自重选 fallback（多选场景靠它收敛）。DOWN 布局的 Left/Right 共用此路径，天然获得
横向 cousin 穿越。回归测试 `Sibling boundary crosses into the neighbouring branch`（topic-select.spec.ts，
自建同侧分支数据 + #map2 第二实例；**实例必须挂 window**，否则后续 evaluate 拿不到）。负对照已做。

实现踩过的三个坑，下次写 DOM-walk 导航直接避开：
1. 祖先兄弟查错层级：容器(chldr)的 sibling 永远是 null（chldr 是 wrapper 最后一个孩子）；
   要查的是**祖先 wrapper** 的 sibling，向上走一步是 wrapper → chldr/me-main → 祖先 wrapper。
2. wrapper > me-parent > me-tpc 固定两层 firstElementChild；childless 分支和子 wrapper 同构，
   不要写成三层。
3. 断言用 `.me-tpc.selected` 而非 `.selected`——me-parent 带 selected class 时 toHaveText 会因
   内层文本假通过。
另：tsc 对「node → container → node」回环赋值会报 TS7022，container 显式标 `Element | null` 即解。
四项绿：208 playwright + 双 tsc + build（grep=0）。
