## ⚠️ 严重事故：git 对象库损坏导致 pull 全面失效（已修复）

### 症状
- `git fsck` 报 15 个 `missing blob` + 10 个 `invalid sha1 pointer`（坏 ref）
- `git pull` / `git fetch` **直接 fatal**：`bad object 3f402393...` + `did not send all necessary objects`
- `git status` 报 `fatal: unable to read <sha>`
- 用户以为「最近的提交都没了」

### 根因（**非 AI 造成，是 GitKraken 的 gc/repack 中断**）
- 证据：`.git/gk/config`（GitKraken 标记）显示分支 `next/v6` 于 16:55 被访问；`.git/objects` 目录 17:04；
  两个 pack 文件 17:05 / 17:15 被重写。
- 机制：gc/repack 过程中 loose objects 被清理，但**引用它们的 index 指针和 refs 没同步**，对象悬空。
- **pull 失败的精确原因**：坏 ref `refs/remotes/origin/feat/svg-render → 3f402393...`（对象不存在）。
  git fetch 协商阶段要遍历全部本地 remote refs，读到坏指针就 fatal 中止 → **整个 fetch/pull 全废**。

### 修复步骤（已验证有效）
1. **先备份**：`cp .git/packed-refs .git/refs-backup-20260913/packed-refs.bak`
2. **定位所有坏 ref**：
   ```bash
   git for-each-ref --format='%(refname) %(objectname)' | while read ref sha; do
     git cat-file -e "$sha" 2>/dev/null || echo "BAD $ref $sha"; done
   ```
3. **删除 9 个坏 ref**（3 个 `refs/remotes/origin/*` + 6 个 `refs/tags/*`）：
   `git update-ref -d <refname>` —— 远端有这些分支/tag，fetch 后自动重建，**零数据损失**
4. **fetch 恢复**：`git fetch --all` → 5 个分支全部成功
5. **清残留**：4 个 skill 文件（customize-markdown / integrate-mind-elixir / plaintext-format /
   streaming-mindmap）HEAD 里有但磁盘缺失 → `git checkout HEAD -- skills/<...>`

### 关键事实（下次直接抄）
- **坏 ref 会让 pull 彻底瘫痪**，但它指向的对象本就不存在，删掉零损失 —— **优先修这个**。
- `git fsck` 的 `missing blob` 若集中在 `refs/remotes/*` 和旧 `refs/tags/*`，是历史远端快照被清理，
  **与本地分支无关**；用 `git rev-list --count HEAD` + `git log` 立刻能证明本地提交完好。
- **用户的「提交没了」是误判**：本地 `next/v6` HEAD `38fb23c` 与 `origin/next/v6` 的共同祖先就是它自己，
  `git rev-list --left-right --count next/v6...origin/next/v6` = `0 30`（领先 0 / 落后 30）
  → 只是没拉取，一条都没丢。
- **切勿用 `git restore --source=HEAD -- <dir>` 恢复「HEAD 中不存在的路径」**：它会**删除工作区该路径**，
  引发级联删除（本次把整个 `src/` 删了，靠 `git checkout HEAD -- src/` 才救回 74 个文件）。
  正确恢复命令：`git checkout HEAD -- <path>`。
- `git restore`/底层 unlink 删除的文件**不进回收站**，误删后无法从回收站找回。

## Outliner 增量渲染 + 事件委托落地（当日 22:0x–22:5x）

起因：用户报「`…` 菜单显示有 glitch 感」，追问后要求以高性能为目标审查 outliner。
先做了实测审查（见下），用户拍板做 **P0 增量渲染 + P1 事件委托**。

**改动范围**（仅 3 个文件，未碰测试）：`src/outliner/Outliner.ts`、`icons.ts`、`outliner.css`。

- `render()` 从 `itemsEl.innerHTML = ''` 全量重建改为 **keyed 增量 diff**：`views: Map<id, ItemView>`
  持久持有每个节点的 DOM；`syncItem` 遍历可见树 + 按 `cursor.nextSibling` 保序（每个移动节点最多
  一次 `insertBefore`）；`patchItemView` 只写变化项；`unmountUnseen` 释放未访问的 view（折叠真的会
  释放子树 DOM）。
- 每节点 **8 个监听器 → 0**：全部改为 `this.el` 上的委托（click 路由 + 5 个拖拽处理器）；
  `createItemView` 刻意不绑任何监听器。
- **消灭创建期闭包**：菜单项带 `data-action`，点击/拖拽处理器读 `view.item / level / parentId /
  siblingCount`（每次 sync 刷新）。旧闭包在节点移动后就是脏的，而增量渲染下元素不会重建 → 必须改。
- 菜单不再走 `render()`：`setOpenMenu` 只动涉及的两个节点；下拉是派生状态，由 `syncDropdown` 同步。
  CSS 侧新增 `.outline-item-wrapper.menu-open` 让按钮组显示**不再依赖 `:hover`**（这正是闪烁根源），
  并给 dropdown 加 `@keyframes` 入场动画。
- topic 写入加缓存（`topicText` / `topicDirty`），编辑中的节点不覆盖；顺带**菜单开关不再对每个节点
  重跑 markdown/KaTeX**。
- `focusItem` 显式把光标放到末尾：元素被复用时已聚焦，不会触发 `focusin`，而旧的全量重建总是
  以「光标在末尾」结束。`svgIcon` 加字符串缓存。

## ✅ 修掉 `requestSync` 丢弃同步请求（当日 23:0x，先写失败测试再改）

修法不是"脏标记 + 补 flush"（那会让每次折叠多渲染一次），而是**把两条通知通道分开**：
- **历史栈通道**（`stack.subscribe` → `requestSync`）**保持同步渲染**。它每来一条就是一次新变更，
  不能让窗口去重；`applyBoundOperation` 随后的 `focusItem` 也依赖它拿到新 DOM。
- **地图 `expandNode` 事件通道**（`bus.addListener` → 新增的 `scheduleSync`）**延后到 microtask**。
  依据（`interact.ts:447/452` 的固定顺序）：带历史的折叠先 fire `expandNode` 再 fire `operation`，
  后者会同步渲染并覆盖前者；而**静默展开**（`nodeOperation.ts:45/255`，`{silent:true}`）只 fire
  `expandNode`、由调用方稍后的 operation 代表它入栈。所以延后即可，两种情形都不会丢。
- 字段：`syncScheduled` → `syncDirty` + `syncQueued`。`requestSync` 里清 `syncDirty`（同步渲染已覆盖）；
  `zoomTo` 自己渲染前也清；`destroy()` 清，避免待渲染的 microtask 回填已清空的容器。

**先把 bug 钉成失败测试**（`tests/outliner.spec.ts` 新增 2 例，未修前两例都失败）：
同一次 `page.evaluate` 里连做两次 `mind.addChild` → 地图两个节点都在、大纲只有第一个，
且**永久陈旧**（没有别的通道会补救）；以及同块内 add + remove → 被删节点仍留在大纲。
注意 `mind.findEle(id)` **内部会自己加 `me` 前缀**，传 `'branch1'` 而不是 `'mebranch1'`。

**验证**：
- `tsc --noEmit` 干净；全量套件 **149/149 passed**（原 147 + 新 2）。
- 新写探针 `skills/mind-elixir-perf-probe/scripts/probe-sync-counts.mjs`（18/18 PASS）：折叠 1 次渲染
  （**与旧去重持平，未退化**）／同块两次操作 2 次且都在 DOM／add+remove 2 次且已删／静默展开
  同步 0 次 + microtask 1 次／撤销、重做各 1 次／`destroy()` 取消待渲染。
- 复测耗时无退化：5,461 节点 空闲 1.04ms、折叠 1.03ms、菜单 0.02ms（基线 1.035 / 0.970 / 0.015）。
- 菜单 12/12、拖拽 12/12 复跑仍全过。

**明确不做**（数据说话：独立模式一次编辑 2.6ms，其中 render 1ms；绑定模式大纲侧只占整次编辑的 0.9%，
其余 99% 是 mind-elixir 自己的 `reshapeNode`）→ 优化 `commit` 的重复全树序列化、建 id 索引、
清理零碎热路径，每项上限约 1ms，不值得改，已从任务列表删掉。
